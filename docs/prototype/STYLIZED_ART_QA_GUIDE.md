# 《牧羊人》正式 3D 美術風格可行性測試（縫紉工作區）

> 2026-11-16。美術技術驗證，不是正式場景替換。沒有改服飾店、廚房、餐廳、移動、提燈、謎題，也沒有改專案的全域光照、材質或攝影機設定。

## 啟動與操作

1. Unity 2022.3.18f1（URP 14、Forward+）打開 `unity/`。
2. 選單 **Shepherd → Prototype → 正式美術風格 QA（縫紉工作區）**：開啟 `Assets/Exploration/Scenes/StylizedArtQA.unity` 並 Play。
3. 點一下 Game 畫面鎖定滑鼠。

| 按鍵 | 功能 |
|---|---|
| WASD／Shift／滑鼠 | 第一人稱走動（正式移動參數：步行 1.5、快走 2.4） |
| **T** | 暖光（午後窗光＋檯燈）／冷光（陰天藍光） |
| **M** | 材質：手繪風格 shader → URP Lit（同一張貼圖）→ 灰盒 |
| **G** | 線框疊圖（顯示真正的多邊形結構） |
| **1～6** | 正面／側面／背面／45 度（環繞視角：牆改成只投影）／第一人稱正常距離／第一人稱近距離 |
| Esc／按住 Alt／U | 放開滑鼠／點按鈕／隱藏標籤 |

重建場景：**Shepherd → Prototype → 正式美術風格 QA 重建場景**。自動截圖：`-executeMethod Shepherd.Exploration.Editor.StylizedArtQAEditor.CaptureFromCommandLine -captureDir <資料夾>`。

## 製作流程（實際使用的方法）

1. **建模（Blender 5.2，`tools/blender/stylized_qa/build.py`，全部程式化可重跑）**：用 bmesh 建立真正的立體零件：
   - 倒角方塊（單段倒角＝一條切面）
   - 錐形桌腳
   - 超橢圓斷面放樣：縫紉機機臂的弧線、椅背的彎板、後腳
   - 車削：手輪、線軸
   - 布料：交錯三角化的網格，越往下摺痕越深，下擺做成鋸齒，對應參考圖 A 披風的撕裂邊

   全部平面著色（flat shading），讓每個面成為一塊色面。沒有任何貼片、看板或圖片平面。
2. **貼圖**：每件資產先 Smart UV，再用 Cycles 的 Emission 烘焙，把下面幾層烘成一張手繪底色：
   - 固有色
   - 色塊筆觸（雜訊做色階化）
   - 上亮下暗的大漸層
   - 凹處混入偏冷的暗色（AO）
   - 邊緣提亮（Bevel 法線差）

   光照方向**不**烘進去。
3. **匯出**：FBX（套用變換、Unity 軸向），貼圖用 PNG。Blender 原始檔是 `tools/blender/stylized_qa/stylized_qa_assets.blend`（貼圖已打包）。
4. **Unity shader `Shepherd/PainterlyLit`**（`Assets/Exploration/StyleQA/Shaders`）：
   - 主光源的 N·L 分成暗／中／亮三段，段與段之間只留很窄的過渡。
   - 接收到的陰影一律落在暗段。
   - 暗面＝壓平過的環境光 × 偏冷偏紫的色調（不是單純變黑）。
   - 點光也分段。
   - 金屬用硬邊高光塊。
   - 沒有描邊。
5. **QA 場景**：`StylizedArtQAEditor` 負責擺放資產、建立材質、加上碰撞、燈光與 6 個觀察點。`StylizedArtQA` 負責走動和切換。

## 與參考圖比較

**已達成**
- 真正的 3D 模型：四個方向和線框都成立，在 Unity 裡可以自由走動、轉角度。
- 大塊色面加切面的語言：桌面倒角、機臂的稜面、手輪的多邊形外緣、布料的三角切面和鋸齒下擺。
- 三段明暗。窗格的投影在桌面和地板形成清楚的光塊，最接近參考圖 B 的氛圍。
- 材質讀得出來：木頭（暖棕）、黑漆加金飾的金屬、黃銅高光、布料。
- 和灰盒對照，灰盒感已經明顯消失。
- 製作是程式化的，可以重跑、可以批量化：家具零件函式可以重複使用，烘焙和匯出一鍵完成。

**還有差距**
1. **貼圖不夠「畫」**：參考圖 A 的色面有刻意的筆觸方向與色溫變化。程式雜訊色階化只做到「斑駁」，近看像水漬（桌面最明顯），不像手繪筆觸。
2. **暗面還偏濁**：暖光下暗面接近黑棕，參考圖的暗面是有彩度的紫褐色。偏色和環境光需要逐場景再調。
3. **飽和度**：暖光照在橘棕木頭上會偏橘、偏亮。參考圖的亮面比較接近奶油色。
4. **造型設計感不足**：比例正確，但輪廓還是「寫實尺寸的家具」，缺少參考圖 A 那種刻意誇張的厚薄對比與不對稱。
5. **冷光**：冷光太暗，資產落在牆影裡時幾乎看不出材質。
6. **布料**：布料只有單面（shader 雙面渲染），近看邊緣很薄；摺痕是程式公式，不夠自然。
7. **小物件**：線軸、針板這類小物件在第一人稱距離下太小，細節看不出來。

**瓶頸在哪裡**
- **建模**：可行，不是瓶頸。硬表面家具用程式化 bmesh 很有效率。但「設計過的輪廓」需要美術先畫出造型稿或剪影，再照著建模。
- **貼圖**：這是**最大的瓶頸**。程式化烘焙可以做出底色和凹凸感，但做不出有方向、有意圖的筆觸。正式品質需要：
  - 在 Blender／Substance 裡手繪一層筆觸，或用美術畫的筆刷貼圖做投影；
  - 或者在烘焙時加入「沿著零件主軸方向的筆觸貼圖」（下一步可以先試這個）。
- **Shader**：主體可行。還缺：
  - 依物件調整的暗面色相
  - 明暗交界處的彩度提升
  - 冷暖光下自動調整環境光
- **工具能力**：Blender 加 Unity 的管線完整打通。限制在於我沒辦法真正「拿筆畫」，所以手繪層需要美術或筆刷素材庫（下載需要你同意）。

## 第二部分：第一人稱左手提燈（2026-11-16）

同一個 QA 場景，進去就會看到左手提著 Blender 做的提燈。**正式遊戲的提燈和手（LanternRig）沒有改**，等你確認之後再換。

| **L** | 提燈開／關（光和玻璃一起變暗） |

4. **右手和槍還沒做**：這次只做左手提燈。
5. **還沒換進正式遊戲**：手和提燈沒有接進正式遊戲的提燈原型（真實顯示、聚光、開關）。

### 手重做、提把加粗（使用者回饋：手太醜、提把太細）

- **手改成用骨架一節一節算出來**：
  - 照解剖比例：近節 ≈ 中節＋遠節；中指最長，其次是無名指、食指，小指最短。
  - 每根手指是一條連續的管子：關節處微鼓、指尖收圓，並且有指甲。
  - 指根連成一條弧線（中指最前面）。
  - 加上拇指根部的肌肉；拇指從手腕旁長出來，繞過提把壓在食指中節。
  - 改用平滑著色：手是有機形體，交給 shader 的三段明暗做出插畫色塊。
  - 無指手套蓋到近節的一半，之後露出皮膚。
- **握的角度是實際算過的**：手指和手掌圍出來的空間，內切圓半徑約 9 mm，剛好握住加粗後的提把（斷面 16×13 mm，原本是 11×9 mm）。提把兩側的轉軸也一起加大。
- **右手**（`SQA_ArmRight.fbx`）：用同一套程式做成鏡像，姿勢是手指微彎的預備姿勢，放在畫面右下角，之後換成握穩定器或其他道具的姿勢。按 R 可以顯示或隱藏。
- 第一人稱的雙手放大到 1.12 倍。這是第一人稱遊戲常見的做法，手讀起來才清楚。
- 查到的資料：網路上關於第一人稱手臂比例的公開資料很少，大多只是武器 FOV 和位置的設定。解剖比例參考了指骨長度的研究（PMC6760092）。

### 握法修正（使用者回饋：手是側著的、沒有握住提把、要掌心朝下、不能穿模）

- **原因**：之前把整隻手臂（含手）一起斜擺讓前臂從左下角進來，手跟著歪了約 45°，提把就沒有穿過拳心。
- **改法**：
  - 手和前臂拆成兩個物件，在手腕接起來，皮帶蓋住接縫。這也是一般第一人稱遊戲的做法。
  - 手永遠保持掌心朝下、指節連線水平，跟提把同一個方向，只跟鏡頭的水平方向轉。
  - 前臂另外朝畫面左下角外面伸出去，不管低頭抬頭，都從畫面邊緣進來。
- **提燈的擺動**：只繞提把這條軸前後擺，提把在拳心裡轉；轉頭時拳頭連同提燈只輕微側傾，提把不會離開拳心。
- **不穿模**：
  - 每根手指的彎曲角度用程式搜尋，條件是手指中心線離提把中心至少「提把斷面半對角線＋手指厚度一半＋0.8 mm」，在這個條件下繞得越緊越好。小指的指根往前移了一點，才繞得過去。
  - 拇指往內收，提把頂端的平直段加寬到 ±6.2 cm，拇指碰不到往下彎的那兩段。
  - 提把斷面改成 15×12 mm（仍然比最早的 11×9 mm 粗）。
  - 手和提燈改回同一個比例（握拳是照提把粗細算的，比例不同就會穿模）。
  - Blender 的碰撞檢查（BVH）：手和提燈重疊的三角形 **0 個**；提把表面到手指最近 2.2 mm。
- **右手**：預設收起來（按 R 可以叫出來看），等決定要拿什麼再做握法。

### 手固定在畫面上、高度、自然晃動（使用者回饋：抬頭時燈跟著舉高、燈像定死）

- **固定在視角上**：手和提燈整組跟著視角走（一般第一人稱的做法），抬頭、平視、低頭時，握把在畫面的位置都一樣（量測結果都是 25%、27%）。
- **高度**：拳頭在畫面左下、離底部約四分之一。手和提燈一起縮成 0.8 倍再放遠一點，燈身才進得了畫面，這也是第一人稱遊戲常見的做法。一起縮放，所以握拳和提把的貼合不變。F 可以把燈舉高。
- **自然晃動**：
  - **手**：走路時一步上下約 1.2 cm；站著時有很慢的呼吸起伏；轉視角時手會稍微落後再跟上（阻尼彈簧）。
  - **提燈**：照轉動的速度甩動，像鐘擺來回幾下才停。實測快速右轉 30°，最大擺動 13°，約 1.3 秒回穩。走路時燈前後晃，站著也有一點餘擺。
- 截圖：`stylized_art_qa/lantern_view_pitch_check.jpg`（抬頭／平視／低頭／轉頭時的擺動）。

### 兩種狀態＋真正的手臂（使用者回饋：手臂太細、平常不要看到燈、按 F 才抬手展示）

- **平常走路**：手垂在身側提著燈，手肘約 72°，握把在畫面下方外面，看不到手和燈，燈光還在。
- **按 F**：開／關提燈。手約 0.4 秒抬起來，路徑帶一點往前的弧度，手肘打開到約 119°，整盞燈和光都在畫面左半邊。停留後放回去，放下約 0.6 秒，總共約 2.4 秒。**按住滑鼠右鍵**可以一直舉著。
- **手臂**：上臂、手肘、前臂三段。
  - 前臂照真人形狀做：靠手肘那端粗（約 11 cm）、往手腕收細，上側有肌肉隆起。
  - 手肘位置用兩節骨頭的 IK 即時算出來：肩膀固定在鏡頭座標，手肘往外下方彎，前臂和上臂長度照算出來的距離伸縮，關節不會分開。
- 截圖：`stylized_art_qa/lantern_two_states.jpg`。

### 舉燈時手臂太長、太直的修正

- **原因**：舉燈時拳頭在畫面中間偏左（橫向 32%、高度 47%）。從這裡伸出畫面，最短也要約半個畫面高，所以只調手肘救不回來。加上手掌保持水平，前臂只能平平地往後伸，就像一根棍子。
- **修正**（骨頭長度不變，提燈大小、高度不變）：
  1. 舉燈時拳頭往畫面左邊靠：橫向 32% → 13%，高度維持 47%，整盞燈仍然完整在畫面裡。這是參考圖第一人稱示意的構圖：拳頭靠近畫面邊緣，前臂很快就出畫面。
  2. 拳頭繞提把這條軸往前轉約 40°，手腕落到拳頭下方，前臂順著手腕方向往下接，手腕不會折。提把仍在拳心，提燈仍垂直下掛（提燈另外算旋轉）。
  3. 手臂錨點（肩膀）和手肘方向用程式搜尋。條件：肩膀和手肘（含粗細）都在畫面外、手肘夾角 60～115°、手肘比手腕低、前臂順著手腕方向。目標：畫面裡的手臂最短、遮到提燈最少。結果手肘約 67°，貼近身體。
- **量測**（同一個平視鏡頭）：畫面裡看得到的前臂 **52% → 10%**（以畫面高度為 100%）；上臂 0%；前臂遮到提燈 3%。

### 舉燈手臂 v2：從左下角往前伸（使用者回饋：手臂從下往上插、像柱子，應該再平一點）

- **原因**：上一版把手肘藏在提燈正下方，前臂由下往上接到手腕，又和畫面平行、離鏡頭很近，看起來像一大片板子。袖子是整片亮米白色、沒有皺褶，最搶眼。
- **修正**（四點）：
  1. **方向**：手肘在鏡頭左下後方，前臂從畫面左下角往前、往右伸到手，近大遠小。手肘約 102°（自然彎曲），手肘本身在畫面外。拳頭在畫面左下約四分之一，燈掛在下面，整盞看得到。
  2. **獨立的手臂鏡頭**：手和提燈改由第 31 層、視角 50° 的疊加鏡頭來畫（主畫面是 62°），手臂不會被拉得很大，也不會穿進牆或家具。正式的 LanternRig 也是這個做法。
  3. **袖子**：改成深暖灰（參考圖角色的內衫顏色），沿長度加柔和的布摺；手腕加一圈斜纏的米白布，蓋住手套和袖子的接縫。
  4. **低頭抬頭只跟 60%**：低頭時手留在身前，手臂不會變成直立的柱子；抬頭時手自然往畫面下方退。
