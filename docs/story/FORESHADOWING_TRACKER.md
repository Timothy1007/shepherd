## 2026-11-06｜Case01 v0.3 的伏筆調整
- `ARC-001`：女兒的真正去向仍為**未決的長線人物問題**，不得在第一案用任何對話或戰利品把死活說成確定。
- `FP-001`：母女合照目前是**優先考慮的跨案件主要證物**；在玩家拿到時可能模糊，在事務所檔案仍保留其原先應有兩人的調查描述。『未來突然出現某人的臉』僅為可能回應，不是已確定事件。
- `FP-002`：17 號鑰匙退為可選證物；**不等於核**，不保證後續可以開所有不存在的門。
- `FP-004`：舊版『不要再讓他們把十七號拿走』台詞尚未定，**不能當作正式後續伏筆**。
- 新增候選 `FP-005`：關於過去異域是否曾被不完整校正的殘留檔案／異常術式痕跡。未確認其真實性，不能當正式主線揭露。
- 證物主題是**見證已發生但正在被否認的生活**，不是收集一堆神祕的發光物品。

# 《牧羊人》伏筆與跨案件證物追蹤
版本：v0.1｜2026-11-06｜**敘事策劃文件；包含尚未確認的候選，不代表程式內已有物品**

## 1. 使用規則
- 每個伏筆、重要證物使用穩定 ID，出現時記錄玩家看到的原始信息與**當下能合理理解**的內容。
- 記錄未來回應的可能路徑，但未定的故事答案**標示未決**；不得後製「早就設定好了」。
- 新寫劇情／新增觸發器時，引用同一 ID；舊伏筆要刪改則更新所有關聯文件。
- 「被玩家看見」不等於「放入玩家道具欄」；某些伏筆只是環境／對白。
- 錯過可選收集物不可鎖死主線；為必要資訊提供回顧或補線索管道。
- 收集品內容與已解鎖狀態應跨場景保留；需要在重返事務所可檢視。完整存檔及跨版本遷移屬後續工程任務。

## 3. 遺留證物資料欄位（建議，不是現有 C# API）
```text
EvidenceId          // 例如 FP-001，不與普通調查旗標共用 ID
OriginCaseId        // case01
Acquired            // 是否實際取得；重要主線不可只靠此 bool
DisplayTitle        // 玩家當前可見標題
DescriptionVersion  // 可由已完成事件變化，但必須有明確解鎖條件
SeenRevealIds       // 已見過哪些後續揭露，避免反覆播放
LinkedStoryNodeIds  // 實際顯現／交談的引用
Status              // Proposed / Approved / Implemented / Revealed
```
**隱藏劇情真相不要塞進玩家可存取／可顯示文字**；編劇文檔可以保留解釋方向，遊戲資產只放對應章節允許揭露的內容。

## 4. 第一案的最小建議
- **1 件主要遺留證物**（暫選照片或鑰匙，尚未決定哪一件可以帶回）。
- **1–2 條無法完全解釋的環境／文本線索**；不必每件都可拾取。
- 一個在 Case 01 可結案的直接目標（異域反應暫時解除、委託得到階段性回報），以及一個被延後處理的長線人物問題（女兒真正去向）。
- 如果證物為主線關鍵，提供回事務所後自動歸檔等防漏設計；如果是隱藏發現，後續只解鎖增補對話／特殊調查。
