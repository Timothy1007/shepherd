# CASE01｜「核修復」玩法重設 v0.3｜Claude Code 實作規格
日期：2026-11-08｜性質：**可執行的實驗 QA 規格；設計提案，尚非已驗收的正式玩法**
Repo `Timothy1007/shepherd`｜`main`｜Unity 2022.3.18f1

## 0. 玩家真人回饋與設計目標
使用者已實際玩過室內 v0.2，核修復同時存在四個問題：(A) 幾乎不需推理、(B) 穿門折返像跑腿、(C) 完成後看不到自己修復了什麼、(D) 不懂為什麼走門等於修復。
本案修復的遊戲語言應是：**比對被改寫的空間關係 → 釐清真實關聯 → 主動維持一條可信連結 → 讓另一條錯誤關聯解消 → 親眼看到屋內與核局部復位**。不是單純「找到 △ 選 △，走兩趟門」。
每案有不同失序法則；此機制僅屬第十七號門，不可變成全遊戲固定三步標準。
既有劇情硬限制：艾琳主動調查異域；母女有溫暖也有矛盾；核局部穩定，不代表救回艾琳；首次校正隱瞞決策、人工失序組織與艾琳結局不得揭露或寫死。

## 2. 提議的核心玩法：「關係校正」而非「走路驗證」
### 要學會的唯一規則（玩家可理解）
「異域會把門口與去向交換。觀察可以證明『現在通往哪裡』；舊地圖和艾琳的記號提供『原來應通往哪裡』。**錨點僅固定一條可信關係，另一條錯接關係需透過交叉觀測與校正操作才能停止重連**。」
玩家應從情境與裝置操作學習此規則，不要用長篇說明一次講完。

### 必須使用既有的三個物件／標記
- △：可信的「書房」關係，來自艾琳筆記與房間內的現實證據。
- ○：可變動關係，指向餐廳／玄關等錯位目的地（沿用程式已有 flip 方向，不新增房間）。
- □／17：缺失的十七號參照，與玄關／舊街區地圖的存在關聯相連。
記號外形、房間布局、門口座標及既有 portal 先不更改。

### v0.3 最小可玩的 5 步流程（一次短鏈，不刷步數）
1. **提出矛盾**：戰後核顯示關聯圖三節點（△ / ○ / 17）與現況去向。舊地圖＋餐廳合照仍是有意義的必備證據。玩家看見「△ 現在錯連餐廳、但記錄標示書房」，若未曾親自見證錯接，提供一次短距離可到達的觀測，不把整套流程鎖死。
2. **判定可信錨點**：在核旁的局部校正裝置上選擇要固定的關係（不是只有對應符號），選項例如「△→書房」、「○→餐廳」、「17→不存在」。從紀錄推理而選對「△→書房」。錯誤時顯示反證：畫面預演哪一條既有關係被擠出、可立即撤銷；不要強制傳送一樓罰跑。
3. **修正第二條關係**：△ 穩定後，○ 仍週期性切換，玩家利用已存在的 17 號參照，在裝置上把「錯誤的 ○ 連結」重新分配到「17→玄關」，使 △→書房與 17→玄關**同時成立**。需有可理解的兩個槽位／連線操作，使用既有符號與房間名（可用可選 UI 或現場 3D 連結線，不須做複雜拖拉 VR 系統）。
4. **一次有意義的實體驗證**：讓玩家**選擇一條**已修好的路線走過（△ 或 17 均可）以「寫回校正」，不再強制兩條路都跑；過門時有 1–2 秒安全、可見的門框幾何歸位與低頻接合聲。裝置同步點亮該連結；若玩家從原本就站在對側，提供附近回程捷徑或直接可驗證入口，避免跑腿。
5. **即時穩定回饋**：核不必再靠第二次按 E 才看出修正；完成後核脈動變穩、走廊錯接終止、局部燈色和 H3 生活細節逐段回歸，仍保留相框空白／第二茶杯缺席／合照淡影。保持前門出口與 FP-001 拾取／3D 檢視不變。

**關鍵約束**：有證據才能判斷，但不能把解法直接寫成「請選第一項」。實體行動只有一次「走一條新連結」且有劇烈可見回饋；補正必須真實改變 routes 與穩定旗標，不得只播動畫後偷偷維持原路由。

## 3. 不要變成選項猜題：資訊呈現與失敗設計
- 裝置上的三個「目前觀測」與三個「舊證據推論」應可逐條查看；顯示「已證實／推定／未知」狀態，不能在玩家尚未觀測時揭露所有答案。
- △ 等記號保留，但旁邊增加可辨識的房間文字、線條方向與視覺差異；色彩不是唯一線索（色弱也能玩）。
- 錯誤錨點不造成永久卡關；顯示**可驗證的矛盾後果**，一鍵撤銷，至少兩種錯誤選項都能恢復。
- 玩家沒有線索時，用日誌與空間事件提示「去哪裡查證」，不要重複空泛訊息。
- 修正關係前可反覆進門測試、房間轉移仍需安全；修正後門的 route map 與顯示一致、不能造成 softlock。
- 維持 8–12 分鐘以內的初次謎題目標（設計目標而非測量結果）；熟練玩家應能明顯更快，避免文字牆和冗長演出。

**這份玩法需先做獨立可切換的 v0.3 QA 分支路徑（同 repo main 內的 feature flag / 獨立 QA 模式，非 Git branch），保留 v0.2 行為以便 A/B 對照。** 不要直接讓所有舊測試壞掉。建議 `Case01CorrectionMode.LegacyV02 / RevisedV03` 或等效選擇，預設一般 QA 保留 Legacy，新增 Unity 菜單「Case01/核校正 v0.3 QA」啟動 Revised。新模式沿用同一室內場景與世界物件，不建立第二套全域 UI。只有使用者實際驗收後再改正式預設。

6. PlayMode：真實場景可移動通過合法路線、可完成新模式、無門卡死、戰後與 H3 仍正常。至少截圖核前、選錯、連結校正中、完成後 1920×1080 / 1280×720。
7. 修改完成後 commit / push `main`，回報確切測試結果及真人尚未驗證點。

## 6. 驗收判準
- 第一次遊玩的使用者能用一句話解釋「為何要鎖定 △、為何另一條錯接仍需修」。
- 至少有一個真實決策：錯選可看見反證，正選有不同的世界狀態；不只是隱藏正確 index。
- 修復至少有兩種空間或燈光視覺回饋，並在 QA 不開日誌也能辨認。
- 相較 v0.2，必要穿門驗證由兩次降低為一次，且不因錯誤回答強迫長距離折返。
- 測試不變的舊模式與新模式均可運作。
