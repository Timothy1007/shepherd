# CASE01〈第十七號門〉｜整棟住宅從零重製任務 v2.0
日期：2026-11-12
狀態：使用者真人否決前次「沉浸式住宅 QA」美術結果；本文件取代該 QA 的**製作方法**，不覆蓋其歷史紀錄或已確認的世界觀／故事。

## 0. 使用者原話所指的驗收缺口
- 「基本重作，用新的規格和標準作，而不是給老東西堆料」。
- 舊 QA 主要沿用 R3 建築、牆地天花、舊家具，附加小物與移速；**不算住宅重製**。
- 真人試玩認為整體仍粗糙，且視角、燈光、手電筒的預期效果沒有明顯看見。自動測試綠燈不構成視覺驗收。
- **禁止再把「新加小物件」「降低步速」「加幾盞燈」當作本任務主要成果。**

## 1. 核心任務與硬限制
- 依 `CASE01_WHOLE_HOUSE_ANOMALY_REDESIGN_V1_0.md` 的**九區功能與逐房生活物件規劃**，重新設計**整棟住宅**的建築布局、各房用途、比例、結構、主要模型、材質、光照與探索動線。
- 正式目標是風格化半寫實 3D（stylized semi-realistic）、英國舊式連棟住宅、現代黑暗都市奇幻、真實有人生活過的住宅。不是豪宅、樣品屋、灰盒、低多邊形積木，也不是照片寫實室內設計圖。
- **舊 R3、Phase1.8/1.9 只供功能、劇情、尺寸缺陷與回歸參考，不可直接以舊牆地天花、樓梯、家具為新住宅的可見主體**。允許重用經逐件審核已達新標準的資產；必須附重用清單與品質理由。嚴禁「整體沿用舊場景，改燈光與放小物」。
- **從新的建築平面與立面開始**：一樓玄關、客廳、餐廳、廚房、後廚／洗衣間；二樓母親臥室、艾琳臥室、小書房、樓梯平台／走廊。九區是功能區，非強迫九個獨立房間。小書房需符合普通住宅尺度，後廚可兼洗衣間。每房有獨立的生活痕跡與主要視覺識別，跨房證據與劇情保留。
- 保護 main 正式 Demo、舊 QA、卡牌戰鬥、現實校正 QA；**新建獨立 Scene/Builder/Assets 命名空間**，不在使用者驗收前替換正式 Demo。開發前確認 working tree；不覆蓋未提交改動。
- 不在本輪加入追逐、怪物、無限走廊等新玩法；先把正常住宅的品質做好。

## 2. 製作階段與交付門檻（不是要求停留在文字規劃）
### A. 全屋新建築與美術規劃
- 先繪製可核對的一樓／二樓平面、樓梯剖面、各房門窗、街區立面關係、家具占位及實際玩家通道；列每區長寬高、門淨寬、主要視線、可互動點。
- 列出九區各自的**建築結構、固定家具、活動家具、生活用品、近看物件、材質清單、主光源／暗區**。不能只畫客廳而放棄其他區域的設計。
- 明確標註新製作 vs 舊版借用；整屋視覺基礎必須新建。

### B. 一間真正完成度高的**新客廳**作為材質／品質基準
- 新建牆壁厚度、門窗、踢腳線、壁紙／舊漆、地板、天花、壁爐、主要家具與生活陳設；**不得只替換材質覆蓋舊方塊**。
- Blender 可用於模型製作，但禁止僅由簡單幾何拼接、材質缺乏層次就聲稱達標。應有輪廓、倒角、連接細節、合理 UV、PBR 材質（albedo/normal/roughness 等適用圖層）、適當的磨損與布料形態。自製／授權素材均需標明來源與可商用權利。
- 先輸出**Blender 參考渲染與 Unity 同視角實機截圖**，逐項比對差異。不能只提供 Blender 漂亮圖卻在 Unity 看不到。
- 合照必須是可信的家庭照片／畫面，不可把程序人偶當作已完成的正式照片。若無法達標，標記待正式美術資產，不能以文字板或人偶照片宣稱已完成。
- 這一階段就需交付**可玩的新客廳 QA**，讓使用者實測，不是只交文檔。品質未達標不得複製到全屋。

### C. 依相同標準擴展其餘八區
- 待客廳品質基準通過真人驗收後，按新建築圖完成玄關／餐廳／廚房／後廚／兩臥室／小書房／樓梯走廊。每區不得只放基本家具便聲稱完成。
- 走廊、樓梯、房間間保持**真正連續可走**，場景轉接、碰撞、視角、照明一致。
- 每區至少有一項能反映人物或家庭生活的可辨識物件，重要線索具可近看正式載體；不要求所有小物都能互動。

## 3. 視角、照明、手電筒必須「在實際畫面中看得見」
- 第一人稱 QA 提供 1.2／1.5／1.8 m/s 步速、眼高與 FOV 可切換，調整起停慣性與輕微鏡頭動態；**以真人從門口看室內的透視與比例為驗收依據**，不是只在 inspector 有數值。
- 重新建立新住宅燈光：保留少量合理生活燈，讓暗區和光照方向形成對比，材質反光、陰影與環境層次必須在 Unity Game View 清楚可見；不可全屋均勻亮、暗到看不清或一片灰。
- 手持照明設備應有清楚可見的**開／關差異**：同一機位、同一曝光設定下提供兩張對照；照明可真正照亮走廊深處的物件、呈現陰影與材質差異；近距離不過曝。不能只報告「有 Spotlight」。
- 提供同視角、同曝光的**舊版 vs 全新住宅**、**手電筒關 vs 開**、**環境燈關 vs 開**、**FOV/眼高對比**，並附設定值。若肉眼看不出差別即視為未達成。
- 重要近看物件要能真正拿起／放大／翻面（適用時），圖像、文字與材質在 1080p 可辨，世界中的版本與檢視版本一致。

## 4. 獨立 QA 與驗收流程
- 新 Scene 建議 `Assets/Exploration/Scenes/Case01HouseRebuildQA.unity`，選單 `Shepherd/Case01/全屋重製 QA`；可以先交新客廳可玩切片，後續逐房擴建，但**整棟九區重製是本任務的最終目標**。
- QA 保留步速、FOV、眼高、環境燈、手電筒、近看、回入口、重置；除錯 UI 預設隱藏。
- 首次交付：新一二樓格局／資產盤點、**新客廳可玩 QA**、Unity 實機截圖及與 Blender 對照、未達品質清單；使用者驗收後再擴建。不要以「只有文檔／只有 Blender 模型」結案。
- 最終交付：九區連續探索 QA，逐房截圖／實際步行路線、近看物件、材質與光照比對、EditMode/PlayMode 測試、實際資產來源／授權、未達標項目與 commit。
- 自動測試是必要的工程回歸，不是藝術品質驗收。不得用「412/412、18/18」代替真人回饋。
- 不假稱 Blender 參考圖等於 Unity 實機；若環境無法達到指定品質，具體回報限制與缺少的模型／貼圖／工具。

## 5. 立即執行指示
1. `git pull origin main` 並讀本文件、`CASE01_WHOLE_HOUSE_ANOMALY_REDESIGN_V1_0.md`、`CASE01_AUTHOR_BIBLE_V0_5.md`、`CURRENT_HANDOFF.md`。
2. 盤點目前可見的舊 R3 牆、地、天花、家具、燈具；列出**必須淘汰的可見舊資產**，不要在新 QA 直接引用舊建築 builder。
3. 建立全新九區住宅平面與新資產／材質設計，**直接實作新客廳 QA**。
4. 提供同機位 Unity 舊／新、手電筒開／關、環境燈明／暗、FOV 對比，確保差異真正可見。
5. 完成測試、提交 main、回報檔案、QA 入口、截圖、未完成項及 SHA。**客廳真人確認後再擴建其餘八區**。

**一句話驗收：如果把新客廳和上一版截圖放在一起，除了多幾件物品、燈變暗和移速變慢以外看不出建築、材質、家具造型的根本差別，就是失敗。**
