# Case 01｜關卡流程與互動設計 v0.1

## 目標與關鍵原則
- 用原有 `AnomalyStreetDemo` 的 Graybox 地圖作為基礎，但**保留原 Demo 不受改動**；後續以新序章場景或可重用配置測試。

- 各互動有可讀取的線索、明確互動範圍和可見回饋。失敗／重試不能讓玩家卡死。
- 事務所是長期據點，重返時按旗標切換對話與物件狀態，不能每個案件複製一間事務所。

## 場景與入口（建議，非已存在）

3. `DemoEntry.unity`（可選）：初始化 Session，再載入 OfficeDemo；或直接以 OfficeDemo 作 demo 入口。
4. `AnomalyStreetDemo.unity`：保留既有純探索／戰鬥測試用，**不覆蓋**。

## 可執行流程／狀態圖
```text
BOOT -> OFFICE_IDLE
OFFICE_IDLE --閱讀通知--> OFFER_VISIBLE
OFFER_VISIBLE --接取--> CASE_ACCEPTED
CASE_ACCEPTED --門口 E / 確認前往--> STREET_ARRIVAL
STREET_ARRIVAL --蒐集 map, plaque, witness--> CLUES_READY
CLUES_READY --觸發街道折返--> ANOMALY_REVEALED
ANOMALY_REVEALED --靠近17號門/調查點--> ENCOUNTER
ENCOUNTER --戰鬥勝利--> BATTLE_WON
ENCOUNTER --戰敗--> RETRY_PROMPT --重試--> ENCOUNTER
BATTLE_WON --取得鑰匙--> KEY_FOUND
KEY_FOUND --在正確門前校正--> CASE_RESOLVED
CASE_RESOLVED --返回事務所--> OFFICE_EPILOGUE
OFFICE_EPILOGUE -> DEMO_COMPLETE
```
建議事件 ID 為固定字串，防止不同 Scene 的同名物件造成狀態失聯。所有轉場先設定持久狀態，再呼叫 SceneManager 載入目的地；載入後由進度恢復對應階段。

## 玩家操作體驗
- 互動準星只對準可互動物件時顯示「E 調查／E 交談／E 前往」；不使用全局常駐提示牆。
- 近距離檢視／NPC 選項時暫停移動，關閉後恢復滑鼠鎖定，不可同時觸發戰鬥卡牌選取。
- 通訊字幕較短，可與探索並行，重要關鍵字同步入調查手冊；避免遺失劇情。
- 線索可任意順序蒐集，三條全部取得才解鎖折返（也可設兩條＋證詞做低風險比較 QA，但正式 Demo 預設三條）。
- 街道邊界初期以物理阻擋或自然封鎖避免出界；觸發折返後以遮蔽／轉位，避免鏡頭切換過程看到瞬移。
- 主角受傷或戰敗時提供重試，重試不重置已蒐集線索；重新進入戰鬥時使用清楚的戰鬥初始狀態，不帶入戰敗殘值。
- 勝利後返回探索，失序體不可重生；鑰匙與門互動才完成結案。
- 「核」操作用世界中的鑰匙與門，第一版無需新增戰鬥卡牌或改 RoundResolver。

## 首版建議最小互動集合
1. 事務所通知／選擇接案。
2. 事務所門／確認出發。
3. 地圖、門牌、證詞三個調查。
4. 邊界折返、17號門顯現（事件／演出）。
5. 戰鬥遭遇（沿用 BattleController）。
6. 鑰匙與門的校正互動。
7. 返回事務所與結案紀錄。
