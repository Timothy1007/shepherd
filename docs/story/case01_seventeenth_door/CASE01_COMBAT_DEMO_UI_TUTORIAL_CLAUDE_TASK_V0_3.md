## 0. 使用者意圖（不可偏離）
《牧羊人》第一個 Demo 的戰鬥是核心玩法，不只是探索後的過場。使用者認為現有戰鬥邏輯已大致清楚，此輪重點是**表現形式、正式視覺 UI 和教學體驗**；現有戰鬥 HUD 太像測試用。請在保留規則核心下，製作「新手能理解、玩家能做選擇、畫面有作品感」的 Case01 首次戰鬥。
- 允許戰鬥介面**大幅改版**，但僅限新的 Demo/Case01 戰鬥外觀與教學路徑；別順手重做探索 HUD、全域測試戰場、網頁版 UI。
- **不得**為了視覺爽感私自調整三元素、三學派、承接、三連、計算公式、數值、敵人數量、行動順序、卡牌效果和勝負條件。
- 現有術語「燃素／基體／擬合劑」、「實在論／過程哲學／關係論」為目前 Unity v0.1 暫稱；未來世界觀命名有變更可能。UI 文案集中管理，不要散落在畫面程式裡；不得自行把名稱替換為歷史版羊糧錢或耕耘守望收割。
- 教學可以引導，但不能做成無法失敗／只能按照唯一卡牌順序按鈕的假戰鬥；仍需真實連結 BattleController / RoundResolver。
- 此任務與核修復 v0.3、室內 Art Pass 分離；**同時開發時只改自己負責的檔案，避免覆蓋其他開發者的 main 提交**。先 pull main、盤點衝突再寫。

## 2. Demo HUD 美術方向與資訊層級
視覺主題：現代黑暗都市奇幻／英倫調性／理性術式裝置，精緻但易讀；不是中世紀魔法羊皮紙、手機 gacha 介面或霓虹科幻戰鬥 HUD。可採深炭黑、去飽和黃銅、象牙白與三元素辨識色；兼顧 720p / 1080p，效果色須有符號/文字輔助。先建立可替換的 palette/typography/card view style，不把所有美術寫死在單個 1200 行類別。
**視線順序：敵人威脅 → 當回合 3 AP → 手牌 → 術式序列 → 預估效果 → 確認。**
- 上方／戰場內：保持 3D 敵人、失序值、攻擊意圖與狀態可讀，選中敵人突出，不能被巨大面板遮住。避免浮動 UI 亂疊在失序體上。
- 玩家狀態：錨定值、擬態錨定與預計受到的威脅各有明確名字及圖示；不要只顯示一排難懂縮寫。重傷／護盾消耗有溫和明確反饋。
- 學派切換：每回合確認前可切，描述「本回合重點／三元素效果大方向」，初次提示；切換後卡牌文字、預估、視覺立即刷新，不存在 UI 自算公式。
- 手牌：7 張同時看得見或可平滑查看；每張清楚顯示元素、1 AP、簡短效果、當前學派作用。點選／取消可見；詳細說明按 hover 或點擊可讀，不逼玩家記色號；注意窄螢幕遮擋。
- **術式編排為關鍵焦點**：三個槽位與順序清楚，哪張先後、指定哪個敵人、前張承接怎麼影響後張、三連共鳴是否即將啟動一眼可看見。可輕量連線/符文動態視覺化，但**資料只讀 Core preview**。
- 預估面板：將「玩家將得到什麼、目標將受到什麼、敵方預告威脅」以先後順序呈現；非保證情況明標「預估」，不使用會與 RoundResolver 不同的 UI 公式。
- 主按鈕：顯著「確認施放」與次要「取消/撤除已排牌」、「調度」。正式 Demo 不在玩家可見主區顯示「重置戰鬥」開發工具；移至 QA panel/hotkey 且 Case01 正式路徑隱藏。戰敗維持原有重試流程。
- 戰鬥紀錄與詳細詞條留在次級可展開介面；首次戰鬥不預設占滿畫面。
- 動畫微交互：選牌、加入槽位、目標變更、承接成立、三連成立、提交鎖定、傷害/護盾/連結/校正逐步顯示；尊重降低動態與閃爍選項。禁止 1 張卡為了酷炫而等 3 秒、整回合變成不能跳的動畫秀。

### 構圖基準（設計方向，可依 UI 實際調整）
```
┌ 玩家錨定 / 護盾 / AP / 回合 ────────────────────── 學派切換 ┐
│             3D 戰場 + 敵人狀態與攻擊預告                     │
│                                                                    │
│   手牌 7 張（下沿）             術式序列 [1 → 2 → 3]         │
│   牌面摘要＋詳情             承接／共鳴／效果預估／確認施放    │

```
優先確保中央角色沒有被巨型提示框或敵人 UI 擋住；也可以用底部置中術式列，不拘泥示意。

## 3. 首次遭遇教學（玩家在場內學會，而不是看教學百科）
**教學觸發：只在 Case01 首場正式戰鬥首次進入時。** 其他 CombatLab3D、AnomalyStreetDemo 保持現有 QA 行為；可在獨立 QA 直接選「有教學／無教學」作 A/B。
分四個自然節點，每節只交代當下需要做的一件事：
1. **感知威脅**：短句提示敵人「失序值」和下一輪攻擊預告；鏡頭與畫面箭頭指向真實值，玩家可閱讀再繼續。
2. **理解資源與學派**：指出 3 AP / 每張 1 AP，及三學派會改變元素作用；讓玩家在任一學派中檢視牌面，不能強迫只選預設學派。
3. **親自編排一次術式**：玩家選一張牌及合法目標，放入第一槽；系統提示後續承接與三連可嘗試，但不強迫第一次就配三同色。可撤銷、可改目標，見到真實預估。
4. **確認與學習結果**：玩家自行按確認，依實際 BattleEvent 播放結果；第一次承接、共鳴或敵方預告真正生效時出現簡短可略過說明。不論成功或失敗，核心不為教學作弊。
教學的建議時長僅為幾十秒的引導，**不鎖死所有操作直到按唯一正確答案**；允許跳過與重看，簡短提示文字，不新增未定稿的旁白角色台詞。
教學狀態獨立 Case01 session 或 overlay controller，**不進入 RoundResolver、不改 Snapshot、Deck/AI/敵人數值**。即使玩家快速多次點擊、F1 重置、ESC 釋放滑鼠、戰敗重試或跳階段，也不遺留一半開著的提示/遮罩。
玩家會自然學到什麼：
- 「錨定值是生命，擬態錨定先吸收傷害」
- 「回合編排最多三張，順序有差」
- 「學派改變相同元素效果」
- 「承接看上一張，三張同元素觸發共鳴」
- 「敵人有下一回合意圖，可以先算風險」
這些不是開場一次播完，而是第一次需要時分散揭示。

## 4. 命名與視覺敘事
術式編排須能讓玩家感受到自己不是在一般魔法卡牌戰鬥：卡牌是「印」的組件、序列組合成術式；但不要擅自宣告「印」的新正式分類或修改目前已確定三元素效果。敵人狀態呈現「失序」與「校正」的因果，戰鬥勝利能銜接回玩家修復核的探索。
加入戰鬥結果短回顧（傷害、護盾、校正、連結、承接、共鳴），但不得用 UI 自己重算數字或提前改寫勝負。若音效/美術尚無資產，先製作自有可替換效果，避免無授權音源。

## 6. 交付拆分與驗收
### 第一步：可查看的 UI 設計稿＋專用 QA
先在 Unity 的**可運行** Case01 新戰鬥 HUD QA 展示完整一回合，保留 3D 戰場、七張牌、三槽序列、選目標、學派切換、攻擊預估。先讓使用者看 1920×1080、1280×720 的實際截圖；不必急著把每張特效做滿。不能只交 figma 圖或文字規格。
### 第二步：互動教學
完成四節點 contextual guidance、跳過／重看、首次觸發與 F1 重試，維持真實對戰與 BattleController 流程。
### 第三步：施法與擊中回饋
承接連線、三連聚合、能辨識的元素效果、失序值下降／護盾生成／狀態層數變化、勝負與返回探索的過渡；如果資源不足優先做清楚的動作和預估，不為特效犧牲可讀性。

### QA / 測試
- 新獨立「Case01/戰鬥 Demo UI QA」入口：只有這場兩敵戰鬥，教學開／關可切；不必從房屋頭重玩，不污染正式場景。
- 原 `CombatLab3D`、`AnomalyStreetDemo`、Case01 房屋 QA 必須回歸可用。
- EditMode：手牌/學派/序列/承接/共鳴 UI 從真實 Core 更新；合法/非法目標；空序列、調度；跳教學；F1/重試還原；不能重複提交回合。
- PlayMode：首次教學完整走通；手動勝利與戰敗均可回到原流程；計算結果與未改版規則的 golden tests 一致；無 UI overlap/截斷/溢出，尤其 1280×720；連續兩場不殘留 tutorial／音效。
- 真實鍵鼠手感尚須使用者驗收，工具測試不能宣稱等同真人試玩。
- 分階段 commit/push `main`，列出改動路徑、每階段 commit、QA 進入方式和結果。不要對已通過的舊測試撒謊。
