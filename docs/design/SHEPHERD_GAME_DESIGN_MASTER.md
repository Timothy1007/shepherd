## 1. 世界與主題

1. 【已確認】世界是現代、偏英倫氛圍的黑暗都市奇幻。各地出現**異域**，正常現實的規律在其中失序；大眾與組織對其認知程度不同，失序起源保留謎團，不替世界設定唯一已證實的解釋。
2. 【已確認】**失序不等於幻覺**：失序現象可以有實在的結構、碰撞與後果；「是否真實存在」「是否穩定」「是否符合正常秩序」是不同問題。
3. 【已確認】牧羊人是有特定門檻的引領／調查者，不是任何人都能自然成為牧羊人；核心使命是進入異域、調查規律、干預失序、解除維持條件，使正常秩序回歸。成為牧羊人的具體資格與歷程尚需故事文件定稿。
4. 【已確認】**局部穩定**不等於整個異域解除。各異域存在使其持續的核心維持條件；**「錨」**為優先使用的世界觀稱呼。部分舊文件仍稱「核」，應在後續專項整理時逐一核對語義，不能直接全域字串取代。
5. 【已確認】各案件可以有不同的主題、尺度、玩法節奏（室內探索、街區、戰鬥或更開放的環境）；**牧羊人的基礎能力規則保持一致**，讓玩家透過組合與不同環境規則產生變化。不能將全遊戲鎖死為每案都探索一棟房子。

## 2. 能力名稱與設計（特別重要）

**禁止把已棄用的「實／續／繫」三分類當作當前能力名稱或主設計框架；不要在新文案、UI、關卡設計或開發指令中重提。舊卡牌系統的「印」也不得擅自移植成目前 3D 探索系統的正式術語。**

### 2.1 較新的能力方向【已確認的功能意圖】

- **錨定**：留下標記／印記與光帶軌跡，支援空間中的定位、連結或後續操作；具體可作用目標、限制與輸入仍須以專項規格／試玩確認。
- **牽引**：作用於 A、B 兩個目標的固定、連接或融合，亦可移動障礙與物件；不能只把它理解成「按鍵搬箱子」。具體連接、融合規則與可作用物件仍待詳細規格。
- **顯像**：揭露特殊符號、痕跡與被遮蔽的資訊；與提燈的記憶顯現應釐清分工，不得自行宣告完全相同。
- **形塑**：長按對指定區域造成失序／修復性的形態改變，亦可能對敵人造成傷害；作用範圍、代價、敵我判定與視覺演出尚待驗證。

**這四項是較新的共同討論方向，不代表四項都已在正式 Unity 場景完成，也不代表已敲定數值、按鍵、冷卻或所有組合。** 能力的共同設計原則是：探索、戰鬥與修復應盡可能共用同一套可預測的規則，而不是三套互不相干的技能。

### 2.2 舊原型如何看待

- `docs/design/CORE_LOOP_AND_ABILITIES_V1.md`（2026-11-14）記錄「照／定／牽」的**三能力原型**，`docs/prototype/ABILITY_SANDBOX_V0_1_QA.md` 有對應試玩。這些是**實驗及歷史設計**，不可因此覆蓋上面的較新能力方向。
- 提燈「照出記憶」及既有穩定器、擬態錨定、聚光、物件搬運等功能，可能與新能力重疊。**不要擅自刪除、合併、重命名或改鍵**；先提出舊新對照、衝突與遷移方案，交由使用者確認。
- 目前沒有足夠依據宣告四能力的完整戰鬥連招、數值或 UI 已定稿；請不要自行補成正式規則。

## 3. 異域、提燈與記憶

1. 【已確認】第十七號門的預設環境是**褪色態**：偏冷、色彩褪去，但不是一片黑、廢墟或不可辨識的空間。正常日光仍可進入。
2. 【已確認】提燈揭露**記憶中的樣子**：通常較溫暖、有色彩，並可能讓記憶中的結構顯現；**記憶不保證客觀真實**，可能有偏差、遺漏、情緒化的尺度與距離。
3. 【已確認】**記憶門**是異域中通往某段記憶／狀態的特殊門或空間門檻。穿越可能改變時期、場景狀態、感知或視角；**不是每扇普通門都會切換**，也不必所有記憶門都產生相同效果。具體門的數量、位置與觸發尚未定稿。
4. 【已確認】**牧羊人沒有變成孩子**。進入異域的特定記憶段落後，牧羊人可能**被迫以孩子的視角經歷他人的記憶**，例如艾琳童年。降低第一人稱攝影機高度是表現手段，不是肉體返老還童或縮小角色碰撞體的世界觀證據。
5. 【已確認】記憶不必依照現實年齡與時間線排列：可以在孩子視角看見成年艾琳與母親的爭執，作為異域記憶錯位；不能把這類矛盾自動視為程式錯誤。
6. 【已確認】提燈與記憶門職責不同：提燈用來揭露，記憶門用來進入／切換特定記憶情境；可以互相配合，但不能擅自設定「舉燈就自動換年代／變孩子」。
7. 【已實作／待驗收】提燈目前有第一人稱手部與舉燈展示；使用者已接受現階段效果，後續美術升級再統一細修。**不要因新關卡布局工作重做提燈操作或手部**。
8. 【已確認】異域可有「局部穩定」進度，但仍不等於已解除錨；局部穩定的時間尺度、記憶物件是否能永久存在，須依已測原型與專項規則核對。

## 9. 探索移動方向：B｜自由立體探索（2026-11-16 使用者確認）

- 【已確認】採 **B｜自由立體探索**：玩家可以跳躍、站上可承載的物件、利用牽引搬移物件創造高低路線；操作需友善，不以高精度跳台為主要難度。
- 【已確認】保留目前已採用的行走與快走手感；小門檻／低台階宜自動跨步。不是所有高低差都要按跳躍。
- 【已確認】探索挑戰應來自觀察、異域規則、能力組合與空間理解，而非高技巧瞄準或精準跳躍。暫不將完整自由攀爬系統列為本階段必要功能。
- 【已確認】孩子記憶視角是感知視角，不是角色身體變成孩子；不能僅因攝影機降低就自動降低跳躍能力或縮小角色碰撞體。
- 【待測參數】跳躍高度約 0.75 m、自動跨步約 0.25 m，僅為 QA 起始建議；需與目前 CharacterController 膠囊體、重力、碰撞、物件尺寸實測後調整。土狼時間、跳躍緩衝、寬鬆落地與可站立物件防滑為建議 QA 項目，**不是已實作**。
- 【開發順序】先盤點現有第一人稱控制器及牽引／碰撞行為，再在整併後的 QA 入口進行獨立跳躍／物件平台測試；未經使用者試玩確認，不得直接改動正式移動參數或既有房間。服飾店布局應預留立體探索可能，但不能為了測跳躍破壞已確認的布局、謎題與提燈。
