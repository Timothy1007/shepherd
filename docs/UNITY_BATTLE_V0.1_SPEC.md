# 《牧羊人》戰鬥系統 v0.1 Unity 實作規格

Nov 5, 2026 · @蔡明義

## 一、範圍與依據

本文把《牧羊人》戰鬥系統 v0.1 整理成 Unity（C#）可以直接實作的規格，供 Claude Code 在開發環境就緒後建立獨立的可操作戰鬥原型。

- **包含：** 戰鬥規則（回合流程、效果表、承接、三連）、可調數值、規則核心與介面分離的架構、預覽與正式結算共用邏輯、自動化測試案例。
- **不包含：** 探索、事務所、劇情、核與異域結算、恩典與特殊牌、爆擊與臨界值，也不規劃新的網頁介面。
- **這個階段不做：** 不建立或修改 Unity 專案，不修改 GitHub，不再進行新一輪平衡實驗。

**規格來源的優先順序**

1. 本文件。
2. 《戰鬥系統 v0.1 規格（草案）》：其第十到第十三節（勘誤與 TypeScript 架構）由本文取代，其餘內容已併入本文。
3. TypeScript／JavaScript 設計計算器：只作規則對照，不是規格；與本文不同的地方見第八節。
4. main、reboot、roguelike-lab 分支：全部是歷史參考，不得把其中任何一版直接當成最新的三元素規格。

**狀態標示**

- **已確認：** 你明確確認的規則。
- **已採用：** 你建議、本文採用為 v0.1 實作設定的選擇。
- **暫定：** 數值，來自設計計算器的測試，可調整。
- **\[假設\]：** 本文為了讓規則完整而補上的細節，尚未經你確認；第九節集中列出。

## 三、規則：狀態、回合流程與結算順序

一個回合由編排、確認、結算三步組成；下面是原型必須照做的精確順序，已併入第二節的八項設定。學派的正式名稱未定，以下沿用暫稱：實在論、過程哲學、關係論。

**狀態**

| 狀態 | 說明 | 規則 | 標示 |
| --- | --- | --- | --- |
| 錨定值 | 玩家生命值 | 起始 30、上限 40；≤ 0 即戰敗 | 暫定 |
| 擬態錨定 | 護盾 | 先於錨定值吸收敵方傷害；跨回合保留、不衰減、無上限 | 已確認 |
| 失序值 | 敵人生命值 | 歸零代表該敵人解除；全部解除即戰鬥勝利 | 已確認 |
| 壓制 | 降低失序值的作用，所有「造成傷害」的統稱 | 名稱暫定 | 暫定 |
| 持續校正（層） | 附著在單一敵人身上 | 回合末結算：壓制等同層數，之後 −1 | 暫定 |
| 連結（層） | 附著在單一敵人身上，由擬合劑建立 | 上限 4，超出捨去；每回合結束 −1；用法依學派而異 | 性質已確認、數值暫定 |
| 束縛 | 固化產生的一回合標記 | 該敵人本回合分流上限 +1；回合結束清除 | 暫定 |

附著在敵人身上的狀態，會隨該敵人解除而消失。

**回合流程**

1. **回合開始：** 手牌 7 張；選擇學派（確認後鎖定，不消耗 AP）；可使用調度一次（見「空序列與調度」）。
2. **編排：** 從手牌選 0 到 3 張元素牌（每張 1 AP），指定順序與目標；目標必須是此時存活的敵人。介面即時預覽。
3. **確認：** 依 A 段逐張結算。提交後不得追加、撤銷或更換目標；剩餘 AP 失效。
4. **序列之後：** C 段，持續校正結算。
5. **敵方回合：** D 段。
6. **回合結束：** E 段，所有敵人連結 −1、清除束縛，打出的牌進棄牌區，補牌至 7 張。
7. **勝負：** 所有敵人解除時立即勝利，後續階段不再執行（序列中途發生時，剩餘的牌直接棄置）；錨定值 ≤ 0 時立即戰敗。

**A. 序列中的每一張牌**（第 i 張，元素 e，前一張元素 p；第一張沒有 p）

1. 取主要數值 V（第四節）。
2. 三連：若整個序列恰為三張相同元素，V = ⌊V × 1.5⌋。只乘主要數值；轉化量、斷連追加與承接附帶都不乘。
3. 反應：若 p 是燃素，V = V + 1。在三連之後才加，不會被倍率放大。
4. 檢查目標（已採用設定 4）：若編排時指定的目標已被解除，這張牌的**敵方指向部分失效**，且**不消耗**轉化所需的擬態錨定；**自身部分照常結算**。分類見下表。失效的牌仍佔 AP，仍算序列中的一張（三連判定與承接來源）\[假設\]。
5. 依第四節結算效果，複合效果的內部順序固定。
6. 承接附帶：若 p 是基體，擬態錨定 +2；若 p 是擬合劑，連結 +1，目標是連結層數最少的存活敵人（相同時取失序值較高者）。在這張牌的效果之後結算，不因這張牌的敵方指向部分失效而取消 \[假設\]。

| 學派．元素 | 自身部分（照常結算） | 敵方指向部分（目標已解除則失效） |
| --- | --- | --- |
| 實在論．燃素 | 無 | 轉化＋壓制（整體失效，不消耗擬態錨定） |
| 實在論．基體 | 擬態錨定 +V | 無 |
| 實在論．擬合劑 | 擬態錨定 +V，條件再 +2 | 連結 +1 |
| 過程哲學．燃素 | 無 | 校正 +V 層、立即壓制 V |
| 過程哲學．基體 | 本回合校正不衰減、擬態錨定 +3 | 校正 +V 層 |
| 過程哲學．擬合劑 | 回復錨定值 2 | 校正 +V 層、連結 +1 |
| 關係論．燃素 | 無 | 斷連＋壓制 |
| 關係論．基體 | 無 | 連結 +V、束縛 +1 |
| 關係論．擬合劑 | 無 | 連結 +V |

上表的分類是本文依「敵方指向效果失效、獨立的自身增益仍生效」所做的歸類 \[假設\]。「本回合預告攻擊總量」是回合開始時所有存活敵人本回合攻擊值的總和，之後不因敵人解除而重算。

**B. 壓制的結算**（任何來源，包含校正結算與回流）

1. 目標失序值減少 n，最低 0；實際減少量記為 d。
2. 傳導：若當回合選的是關係論，且目標此時還有連結，其他有連結的存活敵人各受 ⌊d × 50%⌋ 壓制；傳導造成的壓制不會再次傳導。以**實際減少量 d** 計算，不用溢出的名義量（已採用設定 5）。目標被這次壓制擊殺時，傳導仍照 d 結算，解除在傳導之後處理 \[假設\]。
3. 斷連的順序（已採用設定 6）：先消耗連結，再結算壓制與傳導；所以斷連把目標連結耗到 0 時，該次壓制不會傳導。
4. 失序值歸零者解除，附著的狀態一併消失。

**C. 序列之後：持續校正**

1. 依敵人編號順序，對每個存活且有校正的敵人壓制等同層數。本回合有穩定則所有校正不衰減；否則 −1。若當回合是過程哲學且該敵人有連結，改為自動消耗 1 層連結來取消該次衰減。
2. 回饋：過程哲學回合中，只要這一步至少有一次校正結算，錨定值 +1（上限 40），每回合最多一次。啟動的立即壓制不是校正結算，不觸發回饋。

**D. 敵方回合**（依敵人編號順序；輪到時已解除的敵人不行動）

1. 取該敵人本回合的預告攻擊值 a。
2. 關係論分流：k = min（該敵人連結層數，2 ＋ 束縛，⌈a ÷ 3⌉）；k > 0 且 a > 0 時，消耗 k 層連結，分流 min（a，3k）點，a 減去分流量，並對該敵人壓制等同分流量（回流，視為壓制，會傳導）。
3. 擬態錨定吸收 min（擬態錨定，a），剩餘扣錨定值；錨定值 ≤ 0 即戰敗，後面的敵人不再行動。
4. 實在論回應：a > 0 且錨定值沒有損失時，對該敵人壓制 3；攻擊值為 0 的回合不觸發；每個敵人的攻擊各自判定。

**E. 回合結束與牌庫**

1. 所有敵人連結 −1（最低 0），清除束縛。
2. 打出的牌進棄牌區。
3. 補牌至 7 張：優先抽牌庫；牌庫抽完時，棄牌區洗回牌庫。v0.1 牌庫全是元素牌，物資保底自動滿足；日後加入特殊牌時，沿用原本的保底與混合補牌架構（起手先抽 5 張物資再混合補牌；手牌物資不足 5 張時先補物資；牌庫沒有物資時提前把棄牌區洗回）。

**空序列與調度**

- **空序列（設定 7）：** 允許提交。A 段沒有任何牌，C、D、E 照常；手牌本來就是 7 張，所以不抽牌。
- **調度（設定 8）：** 每回合一次、0 AP，只能在確認前使用；從手牌（不含已放進編排區的牌）選一張洗回牌庫，再隨機抽一張，可能抽回原牌；不套用物資保底；牌的總數不變。

## 四、效果表

三元素決定「做什麼」，學派決定「作用在哪個層面」；下表九格是**同一張元素牌**在不同學派下的效果，不是九張不同的卡，每張牌單獨可用。所有數值為暫定，必須從設定資料讀取（第五節）。

| 元素（動詞） | 實在論（結構） | 過程哲學（過程） | 關係論（關係） |
| --- | --- | --- | --- |
| 燃素（推動） | **施壓：** ① 轉化：消耗 min（擬態錨定，4 ＋ 2 × 目標連結層數）點擬態錨定 → ② 壓制（V ＋ 轉化量） | **啟動：** ① 校正 +V 層 → ② 壓制 V（只算新增層數，不消耗既有層） | **激化：** ① 斷連：消耗目標 min（連結，2）層連結 → ② 壓制（V ＋ 2 × 消耗層數） |
| 基體（固定） | **構形：** 擬態錨定 +V | **穩定：** ① 校正 +V 層 → ② 本回合校正結算不衰減 → ③ 擬態錨定 +3 | **固化：** ① 連結 +V → ② 該敵人本回合束縛 +1 |
| 擬合劑（轉移） | **適配：** ① 擬態錨定 +V → ② 若本回合預告攻擊總量大於當前擬態錨定，再 +2 → ③ 連結 +1 | **轉移：** ① 校正 +V 層 → ② 回復錨定值 2（上限 40）→ ③ 連結 +1 | **連結：** 連結 +V |

**主要數值 V**（三連倍率與承接反應只作用在這個數字上）

| 學派 | 燃素 | 基體 | 擬合劑 |
| --- | --- | --- | --- |
| 實在論 | 壓制 4 | 擬態錨定 7 | 擬態錨定 3 |
| 過程哲學 | 校正 2 層 | 校正 2 層 | 校正 1 層 |
| 關係論 | 壓制 3 | 連結 1 | 連結 2 |

**學派被動**（只在當回合選擇該學派時生效；擬態錨定、校正、連結等狀態跨學派保留）

| 學派 | 被動 | 內容 |
| --- | --- | --- |
| 實在論 | 回應 | 敵方攻擊 a > 0 且被擬態錨定完全擋下時，對該敵人壓制 3 |
| 過程哲學 | 回饋 | 校正結算時回復錨定值 1，每回合最多一次 |
| 過程哲學 | 延續 | 校正結算時，若該敵人有連結，自動消耗 1 層連結取消該次衰減 |
| 關係論 | 傳導 | 壓制有連結的敵人時，其他有連結的存活敵人受到實際減少量的 50%（無條件捨去） |
| 關係論 | 分流 | 敵方攻擊時自動消耗連結，每層分流 3 點，分流的點數全數轉為對該敵人的壓制 |

**承接**（序列的第一張沒有承接，只影響緊接的下一張，不累積）

| 前一張 | 對下一張牌 | 數值 |
| --- | --- | --- |
| 燃素 | 反應：主要數值 +1 | +1 |
| 基體 | 結構：該牌結算後，擬態錨定 +2 | +2 |
| 擬合劑 | 關聯：該牌結算後，連結 +1，目標為連結最少的存活敵人 | +1 |

**三連（共鳴）：** 同一次序列恰好三張相同元素，這三張牌的主要數值 ×1.5（無條件捨去）。兩張不觸發。3 AP 下三連就是整個序列同一種元素；日後提高 AP 時「恰好三張」怎麼判定尚未決定，v0.1 不實作。

**連結的定位：** 擬合劑建立連結，連結本身不固定削弱敵方攻擊，而是一條可被利用的通道：實在論用它放大攻防轉化，過程哲學用它延續校正，關係論用它傳導、分流與回流。

**預覽與正式結算共用邏輯（硬性規則）**

1. 只有 RoundResolver 計算數值；UI、Controller、Presenter 都不得重算。
2. `Resolve(state, plan, rules)` 不使用亂數、不讀時鐘、不修改輸入的狀態（內部複製），輸出新狀態、事件列表與勝負。
3. 預覽 ＝ 對目前狀態呼叫 Resolve，只顯示結果；正式結算 ＝ 採用 Resolve 回傳的新狀態，再呼叫 DeckService 補牌。
4. 預覽與正式結算的結果是同一個 ResolveResult，所以屬性測試 P1（預覽一致性）必須恆成立。
5. 事件列表同時驅動預覽文字、動畫、紀錄匯出與測試斷言。

**型別草圖**（名稱可調整；避免依賴較新的 C# 語法，先確認 Unity 版本支援什麼）

```csharp
namespace Shepherd.Battle.Core
{
    public enum SchoolKind  { Structure, Process, Relation }  // 暫稱：實在論、過程哲學、關係論
    public enum ElementKind { Ember, Base, Binder }           // 燃素、基體、擬合劑

    public sealed class PlannedCard { public int CardId; public ElementKind Element; public int? TargetEnemyId; }
    public sealed class RoundPlan   { public SchoolKind School; public IReadOnlyList<PlannedCard> Cards; }

    public sealed class BattleState { /* 玩家、敵人、牌庫、手牌、棄牌、回合數 */ public BattleState Clone(); }

    public sealed class ResolveResult
    {
        public BattleState NewState;
        public IReadOnlyList<BattleEvent> Events;
        public BattleOutcome Outcome;      // Ongoing / Victory / Defeat
    }

    public static class RoundResolver
    {
        public static ResolveResult Resolve(BattleState state, RoundPlan plan, RuleSet rules);
    }

    public interface IRandom { int Next(int maxExclusive); }

    public static class DeckService
    {
        public static void Refill(BattleState state, IRandom rng, RuleSet rules);
        public static bool TryRedraw(BattleState state, int cardId, IRandom rng, out int drawnCardId);
    }

    public sealed class BattleController
    {
        public PreviewResult Preview(RoundPlan plan);   // 不改動狀態
        public CommitResult  Commit(RoundPlan plan);    // Resolve → Refill
        public bool TryRedraw(int cardId);
        public BattleSnapshot Snapshot();               // 給 UI 的唯讀快照
    }
}
```

**效果資料與解譯**

- 第四節每個格子的效果，在資料裡是一串有順序的效果指令：壓制、轉化、增減擬態錨定、增減校正、鎖定衰減、回復錨定值、增減連結、斷連、束縛。Core 只有一個解譯器，依指令種類處理。
- 每種指令帶一個「是否敵方指向」屬性，已採用設定 4 因此不必寫在各張牌裡：目標已解除時，敵方指向的指令整體失效，自身指令照常結算。
- 學派被動不寫在牌上，而是掛在 RoundResolver 流程的固定位置：壓制時（傳導）、敵方攻擊開始（分流）、攻擊結算後（回應）、校正結算時（回饋、延續）。第三節的順序因此只存在於流程裡，不分散在各張牌。
- 數值全部來自 RuleSet；資料檔不含任何程式邏輯。

**事件列表**（最少集合）：CardResolved、CardFizzled、Pressure（名義量與實際量）、Conduction、ShieldChanged、AnchorChanged、CorrectionChanged、LinkChanged、EnemyResolved、EnemyActed、Redrawn、Refilled。每個事件記錄來源（第幾張牌或哪個被動）。

**資料夾建議**（本階段不建立）：`Assets/Battle/Core`、`Assets/Battle/Data`、`Assets/Battle/UI`、`Assets/Battle/Tests/EditMode`；`golden_cases.json` 放在測試資料夾。

## 八、計算器的角色與已知偏差

TypeScript／JavaScript 設計計算器只作規則對照，不是規格，也不是產品程式；與本文衝突時以本文為準。原本的計算器檔案保持不動。

| 項目 | 本文（v0.1） | 設計計算器 | 影響 |
| --- | --- | --- | --- |
| 目標選擇 | 玩家編排時指定目標；目標已解除時，敵方指向效果失效 | 依預設規則自動選目標；目標死亡時自動改打其他敵人 | 多目標情境的輸出略偏高 |
| 傳導量 | 以目標實際減少的失序值計算 | 以名義壓制量計算 | 關係論多目標略偏高 |
| 已解除的敵人 | 輪到時已解除的敵人不行動 | 同一個敵方階段內被傳導擊殺的敵人仍會行動（驗證：預期錨定值 30，計算器為 27） | 關係論多目標略偏保守 |
| 調度 | 補回，每回合一次、0 AP | 沒有 | 計算器的牌庫流動不含調度 |
| 基礎攻擊 | 歷史機制，不實裝 | 沒有 | 無 |
| 玩家 | 真人 | 每回合窮舉序列的簡化玩家 | 只能看趨勢，不是平衡結論 |

八個標準算例都是單一敵人，不受前三項偏差影響；多目標的舊模擬數字略有偏差，依你的指示不重跑。

**驗證用的副本：** `multiround_calc_golden_check.js` 是計算器的複本，只改了「傳導用實際量」與「已解除的敵人不行動」兩項，`golden_check.js` 用它核對 `golden_cases.json` 裡能以預設目標表達的 19 個案例。它不是第二份規格，之後若與本文不一致，以本文為準並修正副本。
